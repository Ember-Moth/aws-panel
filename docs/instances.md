# 实例

“实例”页统一展示 EC2、Lightsail 与 Wavelength 实例；创建、生命周期操作和固定 IP 更换都从这里进入，并经过预览与任务执行。支持 AWS 商业分区；中国与 GovCloud 账号可以保存，但不读取其资源。

## 实例列表

- 顶部分段控件切换“全部实例 / EC2 / Lightsail”；次级链接切换到静态 IP、弹性 / Carrier IP、账号区域、Lightsail 可用区域、同步记录和定时同步。
- 筛选栏可按账号、区域、AWS 状态、名称或资源 ID 过滤，并可包含最近同步中未发现的历史记录。每页 25 项。
- 点击某行，右侧详情面板显示网络（公网 IPv4、IPv6、私网地址、Carrier IP、VPC / 子网 / 安全组）、配置（规格、镜像、可用区、磁盘、登录）以及归属与同步时间。
- 对拥有操作权限的成员，详情面板提供该实例可用的操作：EC2 的启动 / 停止 / 重启、更换 IP、启用 IPv6，“更多”中的终止；Lightsail 的更换 IP。每个操作都打开对应的预览页，确认后才提交任务。
- 页头的“创建 Lightsail”进入批量创建；“EC2 工作台”进入 EC2 实时列表、创建与网络准备。

列表与详情读取数据库中的快照，打开页面不会请求 AWS。快照中的状态和 IP 可能已经变化；超过 30 分钟的快照标记为“缓存可能已过期”。

## 同步

| 视图 | AWS 来源 |
| --- | --- |
| 账号区域 | Account `ListRegions`：账号各区域的启用状态 |
| Lightsail 可用区域 | Lightsail `GetRegions`：服务支持的区域与可用区 |
| Lightsail 实例 | Lightsail `GetInstances` |
| Lightsail 静态 IP | Lightsail `GetStaticIps` |
| EC2 实例 | EC2 `DescribeInstances`：AMI / 规格、VPC / 子网、安全组、主网卡、IPv4 / IPv6、根卷删除策略 |
| 弹性 / Carrier IP | EC2 `DescribeAddresses`：分配 ID、绑定对象、网络边界组 |

- **手动同步**：点击“同步资源”，选择连接、类型和区域，一批最多 50 个范围。拥有账号读取权限的成员即可提交，不受云端写入开关影响。
- **定时同步**：间隔 5 至 1440 分钟，从下一个间隔开始运行；错过的时间点不会在重启后集中补发。每次运行使用创建成员的当前权限和连接的当前已验证配置。相同范围已有未完成任务时，本次跳过。
- **同步记录**：每个范围的任务状态、错误、最后成功时间和快照数量。

快照的一致性规则：

- 读取全部分页后才在一个事务中替换快照。分页异常、身份不匹配、权限不足、网络或代理故障都不会用部分结果覆盖旧数据；单范围上限 256 页、20,000 项。
- 只有完整成功的同步才把未出现的记录标为“本次完整同步未发现”，并保留最后观测的数据。这不代表资源已在 AWS 删除。
- 资源身份使用 AWS ARN 或资源 ID，同一账号更换连接不会产生重复记录。
- 对 AWS 的请求按账号、区域和服务限速：默认每秒 4 次、突发 4 次、最多 2 个并发响应。

## 创建 Lightsail

1. 在创建页选择 Lightsail，选择已验证的连接和区域。列表只包含 Lightsail 支持且已启用的区域。
2. 页面自动加载可用区、系统镜像、套餐、SSH 密钥对和配额。套餐按镜像最低规格和 IP 类型（IPv4 + IPv6、仅 IPv6、仅 IPv4）筛选。
3. 选择 SSH 密钥或 root 密码登录，填写实例名称（每行一个或逗号分隔）。可以“添加账号或区域配置”，在多个账号区域同时创建，每批最多 50 个实例。
4. 右侧摘要实时显示实例数、每组配置、按目录价估算的月费和将自动完成的事项。
5. 生成预览，核对每个实例的账号、可用区、镜像版本、套餐、IP 类型、密钥对和月费，然后提交。

支持活动的 Linux / Unix 系统镜像；不支持应用镜像、Windows、Lightsail for Research 和自定义启动脚本。实例名称为 3 至 63 位小写字母、数字或中划线，首尾为字母或数字。面板不下载、保存或展示 SSH 私钥。

**自动完成**：实例进入 running 后，面板通过 `PutInstancePublicPorts` 放行所用地址族的全部公网入站（所有协议、0–65535，IPv4 `0.0.0.0/0`、IPv6 `::/0`），Lightsail 出站默认全部允许；然后分配并绑定静态 IPv4。仅 IPv6 的实例不分配 IPv4。

**价格**：预览按 [GetBundles](https://docs.aws.amazon.com/lightsail/2016-11-28/api-reference/API_GetBundles.html) 返回的套餐月价汇总，不含税费、超额流量、快照等费用，也不计折扣。执行前重新读取目录，价格上升或镜像、规格变化会停止该目标并要求重新预览。

**配额**：只有识别到区域级、明确以 vCPU 计的 Lightsail 实例配额时才计算：现有实例的 vCPU 加上本批新增与上限比较。无权限或无法识别时显示“无法查询”，不声称配额充足。预检不预留配额。

**创建核对**：`CreateInstances` 没有幂等令牌，面板为每个目标单独调用一次并关闭 SDK 自动重试。响应丢失或进程中断后，只读核对同名实例、`aws-panel:` 归属标签和创建操作历史，不直接重发；参数、标签或 ARN 不一致时进入“需要处理”，不认领来源不明的资源。请勿手动修改这些归属标签。

## 创建 EC2

在 EC2 工作台选择“创建实例”：

1. 选择连接和已启用区域，加载镜像、规格、子网、安全组、密钥对和实例。
2. 选择官方 Debian 12 / 13、Ubuntu 24.04 / 26.04 或 Amazon Linux 2023 的当前 AMI（x86_64 或 arm64）。镜像的发布者与架构会被校验，不接受任意 AMI 或自定义 user data。
3. 选择兼容规格和已有子网。系统盘为加密 gp3，容量不低于 AMI 要求；强制 IMDSv2，按需、default tenancy，不使用容量预留。
4. 选择 SSH 密钥或 root 密码，可同时启用 IPv6。
5. 预览后提交。任务依次确认创建归属、running、绑定全放行安全组、分配并绑定弹性 IP。

**全放行安全组**：每个新实例创建专用安全组，放行全部来源、协议和端口的入站与出站（IPv4 `0.0.0.0/0`、IPv6 `::/0`），绑定到主网卡。面板不修改默认或共享安全组。公网 IPv4 仍需要互联网网关路由，IPv6 仍需要规格、子网前缀和默认路由支持；网络 ACL 与系统防火墙独立生效。

**生命周期**：启动、停止、重启、终止和启用 IPv6 都从实例详情进入。

- 创建通过 `RunInstances` ClientToken、归属标签和发送记录共同核对。
- 终止按 AWS 的 DeleteOnTermination 设置删除卷；由面板创建并已核对的固定 IP 会在终止确认后自动释放，无法证明归属的地址与共享网络保留。
- 重启成功只代表 AWS 接受了请求；响应不明时不会从 running 推断重启成功，任务进入“需要处理”。
- “启用 IPv6”只给已有实例的主网卡添加地址，要求子网、路由和安全组已满足条件，不修改共享网络。

JSON 接口支持一次提交最多 50 个创建目标；网页一次配置一个。

## root 密码登录

Lightsail 与 EC2 都可以选择“root 密码（SSH）”，支持 Debian 11 / 12 / 13、Ubuntu 20.04 / 22.04 / 24.04 / 26.04、Amazon Linux 2 / 2023 的系统镜像，其他镜像会禁用该选项。密码 15 至 128 个字符，表单出错后不会回显。

- 密码只在请求处理期间用于生成带随机盐的 SHA512-crypt 哈希；哈希经主密钥加密后保存，绑定创建者、账号和目标参数。计划、任务、预览和审计只保存引用，原密码无法回读。
- 启动脚本只包含密码哈希和固定脚本：检查发行版与 SSH 配置，设置 root 密码并重新加载 SSH，配置失败时恢复原配置，不修改防火墙。
- 实例确认归属后删除面板中的加密哈希；AWS user data 与实例上的初始化资料仍可能保留哈希，应按敏感配置管理。
- 任务显示“实例已运行”与“root 密码初始化已安排”。running 状态不能证明脚本执行完成或密码登录可用。

## 双栈网络准备

在 EC2 工作台选择“网络准备”，指定普通可用区。任务新建：

- VPC `10.42.0.0/16`、子网 `10.42.0.0/24`，以及 AWS 分配的 IPv6 前缀和 /64 子网；
- 互联网网关、独立路由表（IPv4 / IPv6 默认路由指向网关）；
- 允许全部 IPv4 / IPv6 入站与出站的安全组。

不创建 NAT 网关，不修改已有 VPC。每一步都先保存发送记录，按网络标签与资源 ID 核对，中断后只读恢复、不重复创建。失败不会自动删除已创建的资源，任务输出列出全部资源 ID。完成后重新加载创建目录即可选择新子网。

## 更换固定 IP

实例创建时自动分配并绑定固定 IP，不设独立的公网 IP 页面。从实例详情点击“更换 IP”：

1. 先分配新地址（需要一个空余的地址配额）。
2. Lightsail 解绑旧地址、绑定新地址并确认异步操作成功；EC2 用不抢占已有绑定的 `AssociateAddress` 绑定，并确认主网卡、私网 IP、网络边界组和公网 IP。
3. 新绑定确认后自动释放旧地址。

释放的地址无法保证找回，DNS 记录不会自动更新，切换期间连接会中断。分配结果不明时不会重复分配；AWS 异步失败时不会释放旧地址。绑定中的地址不能直接释放。Wavelength 实例分别更换入站 EIP 和出站 Carrier IP，见 [Wavelength](wavelength.md)。

计费提示：Lightsail 静态 IP 绑定时不单独收费，闲置可能收费；EC2 公网 IPv4 无论绑定与否都可能收费。

## 配额

“配额”页按连接、区域和服务查询 Service Quotas 的当前适用值和用量：

- Lightsail：实例 vCPU 与静态 IP。
- EC2：各按需实例类别的 vCPU 与弹性 IP。用量计入运行中的按需实例和 active 容量预留（不重复计数），不含 Spot、专用主机与未运行实例；BYOIP、CoIP 与 Carrier IP 不计入普通弹性 IP 用量。
- VPC：VPC 与互联网网关。

没有权限、分页失败或数据不完整都显示“未知”，不当作零或无限。创建、启动、分配 IP 和网络准备会在预览与执行前检查可确认的配额，本批请求按账号、区域和类别合并计算；预检不预留配额。

## 创建目录缓存

创建表单的选项来自服务端缓存，选择账号与区域后自动加载，不必每次查询 AWS：

| 数据 | 正常复用 | 过期快照最多保留 |
| --- | --- | --- |
| Lightsail 镜像、套餐与价格 | 24 小时 | 7 天 |
| EC2 官方 AMI | 6 小时 | 24 小时 |
| EC2 / Wavelength 可售规格 | 24 小时 | 7 天 |
| 子网、路由、安全组、密钥、可用区、Lightsail 配额 | 2 分钟 | 15 分钟 |
| 账号区域状态（创建表单与区域启用共用） | 10 分钟 | 1 小时 |
| 配额上限 | 1 小时 | 24 小时 |
| 配额用量 | 1 分钟 | 5 分钟 |
| EC2 实例列表与实例地址列表 | 30 秒 | 2 分钟 |
| Wavelength Zone 开通状态 | 2 分钟 | 15 分钟 |

- 超过正常复用时间后，先返回保留期内的快照并在后台刷新；刷新失败不覆盖已有数据，超过保留期必须读取成功。
- 页面显示更新时间与后台刷新状态；“刷新最新”等待 AWS 的最新结果，保留已填写的内容。
- 缓存按服务、账号、连接、连接配置版本、区域和 Wavelength Zone 隔离，返回前仍校验成员权限与连接状态。只缓存展示数据，不缓存凭据。Redis 不可用时退回进程内缓存。
- **预览与任务执行不使用展示缓存**，始终向 AWS 重新校验镜像、规格、价格、网络、区域和配额。

## 接口

JSON 接口前缀为 `/api/v1`：

- 资源：`/resources`、`/resources/{id}`、`/resources/options`、`/resources/scopes`、`/resources/refresh`、`/inventory/schedules`。
- Lightsail：`/lightsail/options`、`/lightsail/regions`、`/lightsail/catalogue`、`/lightsail/plans`、`/lightsail/plans/{id}`、`/lightsail/plans/{id}/submit`。
- EC2：`/ec2/options`、`/ec2/catalogue`、`/ec2/instances`、`/ec2/plans`、`/ec2/plans/{id}`、`/ec2/plans/{id}/submit`。
- 地址：`/addresses/options`、`/addresses/catalogue`、`/addresses/plans`、`/addresses/plans/{id}`、`/addresses/plans/{id}/submit`。
- 配额：`/quotas`、`/quotas/options`、`/quotas/regions`。

目录、区域、实例、地址与配额接口支持可选的 `refresh=true`，响应中的 `freshness` 给出 `updated_at`、`refresh_after`、`cached`、`stale`、`refreshing` 和 `refresh_failed`。完整结构见 [Swagger](../api/generated/swagger.json)。
