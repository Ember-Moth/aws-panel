# 任务中心

所有修改 AWS 的操作，以及资源同步、账号池刷新等较长的读取，都以持久化任务执行。任务页左侧是任务列表，右侧是所选任务的详情：状态、发起人、时间、按目标汇总的进度条、每个目标的步骤与尝试记录，以及按时间排列的进度记录。

## 从预览到任务

1. 在业务页面填写参数并生成预览。预览只读查询 AWS，列出每个目标、预计变更、费用与配额检查，有效期十分钟。
2. 确认预览后提交。提交与审计在同一事务中保存；相同幂等键和相同参数重复提交会返回已有任务。
3. Worker 按目标执行步骤，进度实时推送到任务页。不同目标可以并行，同一目标的步骤依次执行。

单批最多 50 个目标，每个目标最多 16 个步骤。

## 状态

| 状态 | 含义 |
| --- | --- |
| 等待调度 | 已保存，等待队列唤醒；Redis 暂时不可用时任务仍然保留 |
| 正在处理 | Worker 正在执行 |
| 等待再次检查 | 等待 AWS 异步完成、结果核对或有限次重试，页面显示下次检查时间 |
| 已完成 | 所有目标完成 |
| 部分成功 | 部分目标完成，其余失败或取消；成功结果保留 |
| 失败 | 明确失败，或在没有未确认副作用的情况下用完重试次数 |
| 需要处理 | 结果无法确认、权限或配置发生变化、执行器不兼容等，需要处理原因后恢复 |
| 已取消 | 未执行的部分已停止，已发出的请求都有了可解释的结果 |

## 取消

“取消未执行步骤”会停止尚未发出的步骤。可能已被 AWS 接受的请求继续只读核对，无法确认时进入“需要处理”。取消不会删除已经创建的资源；取消后的恢复只继续核对，不会发出新的写请求。

## 恢复

失败或需要处理的步骤旁有复选框。勾选后点击“恢复选中的目标”：

- 系统先核对云端实际结果，确认可以安全继续后才重新执行。
- 使用原来的输入、执行器版本和幂等令牌，追加新的尝试记录，不影响已成功的目标。
- 即使由管理员触发，仍以原发起成员的身份和当前权限执行。
- 更换凭据、代理或角色来源后，先重新验证连接，再勾选“采用这些连接的当前已验证配置”。旧尝试保留原配置记录，新尝试记录实际使用的配置。

## 权限

成员需要对任务涉及的全部账号有读取权限才能查看任务及其事件。发起人和管理员可以取消或恢复；恢复写步骤还需要对所选目标的操作权限，执行时会再次检查发起成员的当前权限。会话或账号授权被撤销后，实时进度推送会停止。

## 可靠性

- **状态以数据库为准**：任务、步骤、事件和待投递消息都保存在 PostgreSQL。Redis 只负责投递引用，不保存凭据或任务状态；消息丢失时，维护循环每秒扫描并补投。
- **执行租约**：每次尝试持有 30 秒租约，每 10 秒续租，并带递增的执行代号。进程退出或失去租约后，接管者先核对云端结果；迟到的旧执行者不能覆盖新结果。
- **不重复写入**：首次调用前保存幂等令牌，重试和接管复用同一令牌。不支持幂等令牌的 AWS 操作，通过发送记录、归属标签和操作历史核对，结果不明时不会直接重发。
- **目标互斥**：同一分区、账号、区域和目标同时只能有一项未完成的操作，“需要处理”的目标也继续占用。互斥只约束本面板，不能约束其他 AWS 客户端。
- **不确定性不会被消除**：只有明确成功、明确失败或确认不存在待核对副作用时，才会离开“需要处理”。
- **执行器版本**：任务固定使用提交时的执行器版本。升级后缺少匹配执行器的任务会暂停在“需要处理”。

## 本地自检

设置 `AWS_PANEL_DIAGNOSTICS=true`（或 `worker.diagnostics: true`）后，管理员可在任务页点击“运行本地自检”，用模拟目标检查提交、进度与恢复，可选正常完成、部分失败、首次暂时失败、等待完成和响应丢失等场景。自检不调用 AWS。

## 接口

计划：`GET /api/v1/plans/{id}`；提交：`POST /api/v1/jobs`，或各业务模块的 `/{模块}/plans/{id}/submit`。任务：`GET /api/v1/jobs`、`GET /api/v1/jobs/{id}`、`POST /api/v1/jobs/{id}/cancel`、`POST /api/v1/jobs/{id}/retry`、`GET /api/v1/jobs/{id}/events`（按序号补读）和 `GET /api/v1/jobs/{id}/stream`（SSE，支持 `Last-Event-ID`）。完整结构见 [Swagger](../api/generated/swagger.json)。
