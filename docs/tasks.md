# 任务中心与恢复

M3 提供持久化计划、任务、逐目标步骤、尝试记录、进度事件和 outbox。M4 已通过 inventory.refresh 接入区域与 Lightsail 资源读取；本地自检仍默认关闭，云端写操作在 M5 接入。

M5a 已注册 regions.enable，云端写入默认由 cloud.writes_enabled=false 禁用。关闭时仍允许预览和已发出请求的只读核对；通用提交入口和实际写请求都执行开关检查。详见 [区域启用](region-operations.md)。

## 使用任务中心

任务页面显示每个目标、步骤结果、尝试记录和最近进度。实时连接断开后自动回退定时刷新；SSE 按任务内事件序号补读。后端每批事件重新检查有效会话和账号范围，撤销会话或账号权限会停止后续输出。

| 状态 | 含义与处理 |
| --- | --- |
| 等待调度 | 任务已存入数据库，等待队列唤醒；Redis 暂时不可用时仍保留 |
| 正在处理 | Worker 持有有效执行租约 |
| 等待再次检查 | 等待云端异步状态、结果核对或有界重试；页面显示下次时间 |
| 已完成 | 所有目标完成 |
| 部分成功 | 部分目标完成，其他目标失败或取消；成功结果保留 |
| 失败 | 已知失败，或在没有未确认副作用时达到预算 |
| 需要处理 | 结果无法确认、权限/配置发生变化、执行器不兼容等，需要处理原因后恢复 |
| 已取消 | 未执行部分已停止，已发出的请求已有可解释结果；不代表删除云资源 |

恢复时勾选失败或需要处理的步骤。系统先核对，再决定是否继续；使用原来的输入、执行器版本和幂等令牌，追加尝试记录，不覆盖成功目标。管理员触发恢复也仍使用原发起成员作为执行人，不借用管理员权限执行。

更换凭据、代理或角色来源后，先重新验证连接，再在恢复表单中选择“采用这些连接的当前已验证配置”。旧计划和尝试记录保留原配置，新尝试记录实际采用的配置。刷新只针对选中的目标，不重新解析已完成目标的连接。

取消会停止尚未发出的步骤。已经可能被 AWS 接受的操作继续只读核对；无法确认时仍进入“需要处理”。取消后的人工恢复只继续核对，不恢复新的写步骤。面板不会把取消解释为删除已经创建的资源。

成员必须对任务涉及的全部账号有读取权限，才能查看该批任务和事件；发起人或管理员可以管理任务。恢复写步骤还需对所选目标有操作权限，且实际执行时会再次检查原发起成员的当前权限。只读成员不能管理云端写任务。

## 可靠性边界

任务和 outbox 在同一个 PostgreSQL 事务中创建，提交审计失败时一起回滚。提交幂等键的作用域是成员和操作；同键同参数返回已有任务，同键不同参数返回冲突。计划默认十分钟有效，当前单批最多 50 个目标，每个目标最多 16 个顺序步骤。

Redis/Asynq 只负责投递引用，不保存明文凭据或作为任务状态来源。outbox 入队成功但标记失败可以重新投递；消费者按数据库状态取得租约，已完成或正由有效执行者处理的步骤不会直接重复执行。数据库扫描还会补投丢失的队列消息。

每次尝试持有租约和递增执行代号。默认租约 30 秒、每十秒续租；结果回写同时验证代号、执行者和租约期限。进程死亡或失去租约后，接管者先调用 Reconcile；迟到结果不能覆盖新执行者的状态。租约不能撤回已经发出的 AWS 请求，因此执行器还必须实现服务自身的幂等和核对规则。

任务恢复保留“不确定”标记，安全重试本身不等于已经确认未产生副作用。预算耗尽时，未确认结果进入 needs_attention；只有明确成功、明确失败或确认不存在待核对副作用后，才能消除不确定状态。

同一 AWS 分区、账号、区域和目标互斥键只能有一项未完成操作；需要处理的目标也继续占用互斥键。不同操作若修改同一云端对象，应使用相同目标键。互斥只协调本面板中的任务，无法约束其他 AWS 客户端。

维护循环默认每秒执行，消息丢失补投窗口默认 30 秒。队列重试最多三次；业务重试次数、截止时间和单次调用超时由固定版本的执行器定义，独立于队列重试。等待期间释放 Worker，不长时间占用执行槽。

## 开发执行器

操作实现 operations/contract.Executor，由 app 注册具体版本。输入须由对应业务模块的强类型 Validate 规范化；Plan 只做读取并生成目标与步骤，不提供任意 AWS API 名称加 JSON 的执行入口。

- Execute 处理当前步骤；Reconcile 只读核对，不能在读取权限下发起新的云端写入。
- 写计划必须提供稳定的 Target.LockKey。公共准备工作使用显式顺序步骤；不同目标可并发。
- Call.Token 在首次执行前持久化，重试和接管继续复用。Call.Previous 提供本步骤已知结果，Call.Completed 提供同一目标之前成功步骤的资源引用。
- 每次外部请求都须调用 Call.Check。AWS SDK 使用 accounts.ConfigForBound，传入计划中的配置指纹和 Call.Check，确保资源请求、STS 刷新和 SDK 重试都受相同租约与授权检查约束。
- 未知结果返回 Waiting；只有可安全重复相同令牌的操作才返回 Retry。ConfirmedAbsent 只用于能够证明没有尚待核对的已接受副作用的情况。
- Output 只保存明确的资源引用、请求 ID 和安全摘要。禁止直接保存 SDK 原始响应、错误字符串或秘密。
- 在途任务按精确执行器版本查找。不兼容部署会暂停相应步骤，需要保留旧版本实现或在升级前排空；不得静默改用新版本。

## 本地自检

```sh
AWS_PANEL_DIAGNOSTICS=true ./bin/aws-panel --config etc/aws-panel.yaml run
```

也可设置 worker.diagnostics: true。此开关默认关闭；启用后管理员可在任务中心发起自检，预览后提交。自检提供正常完成、部分失败、首次暂时失败、等待完成和响应丢失场景，效果写入本地模拟表，不调用 AWS。

API 入口包括 /api/v1/operations/diagnostics/plans、/api/v1/plans/{id}、/api/v1/jobs，以及任务的 /cancel、/retry、/events 和 /stream 子路由。/stream 支持 Last-Event-ID；完整契约见 [Swagger](../api/generated/swagger.json)。

## 验证范围

make smoke 使用隔离的真实 PostgreSQL/Redis，以 race 模式验证事务回滚、提交幂等、实际 Asynq 投递、入队后的 outbox 标记失败、Redis 消息丢失、响应丢失、Worker 子进程退出、过期执行者迟到、结果提交失败、撤权、配置变更、目标互斥、有限重试、取消与选择性恢复。HTTP 验收覆盖任务页面、事件补读、正在输出的 SSE 会话撤销和应用重启后任务完成。

这些验证证明本地任务基础设施与模拟执行器的行为；不能替代具体 AWS 服务操作的真实生命周期、幂等语义与配额验收。AWS 写能力开放前还需完成对应业务执行器和测试账号验收。
