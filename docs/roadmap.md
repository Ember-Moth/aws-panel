# AWS Panel 开发计划

更新日期：2026-11-02。工程骨架基线：b897444；M1 至 M5 本地实现位于当前工作区。

目标是从现有工程骨架逐步交付可供小团队使用的 AWS 管理面板。采用单进程 Go、Hertz、Go template + htmx + Tabler、PostgreSQL、Redis/Asynq，统一北京时间，并为每组 AWS 连接独立配置 SOCKS5 出口。

计划按可验收的里程碑推进。M1/M3 已完成本地验收，M2/M4/M5 已完成本地实现、真实 AWS 验收仍待完成；M6 的本地容器与恢复验收也已完成，真实 AWS 闭环仍待完成。

## M1 身份与权限

主要属主：identity；审计基础由 platform 提供。

交付内容：

- 一次性本地管理员初始化命令、密码哈希、登录、退出、密码修改和可撤销会话。
- 成员创建、禁用及管理员、操作员、只读角色。明确动作授权能力，默认拒绝；账号范围授权在 M2 有真实账号实体后接通。
- Secure/HttpOnly/SameSite Cookie、CSRF、登录限流与受信代理配置，明确本地 HTTP 开发和 HTTPS 部署的差异。
- 登录页、成员管理页、当前成员菜单；未登录访问页面跳转登录，JSON API 返回相应状态，htmx 片段不混入完整登录页。
- 审计表和事务内追加接口，记录登录、退出、成员与角色变更。系统详细状态进入受保护范围，健康探针保留最小公共响应。

验收标准：

- 页面、JSON API 和 HTML 片段都不能通过伪造请求头绕过鉴权。
- 成员禁用、退出和密码修改按既定规则撤销会话；并发操作不能移除最后一个可用管理员。
- 只读成员不能执行成员或资源管理写入，但允许本人退出和改密；非管理员不能管理成员或连接。密码与会话秘密不进入响应和日志，CSRF token 只用于受保护的交互。
- 从初始化管理员到登录、管理成员、退出的浏览器流程通过测试；持久会话在进程重启后按策略生效。

完成后可以交付一个有真实身份边界的团队工作台。

## M2 AWS 账号 凭据与代理

主要属主：accounts；账号授权仍由 identity 拥有。

按三个增量实现：

1. **秘密存储**：外部主密钥、带版本的认证加密、秘密引用、更新与停用；验证错误密钥、密文篡改和轮换过程。连接与任务只保存引用，不复制明文。
2. **账号连接**：AWS 账号和连接分别建模，先接入静态/临时凭据及身份验证，再接入 AssumeRole 和到期刷新；接通成员的账号范围授权。
3. **代理与客户端生命周期**：代理配置、认证秘密、连接绑定、测试结果、配置版本和连接池失效；API、STS 和后续任务共用同一出口解析路径。

页面包括账号列表、账号详情、连接编辑、代理配置与分层连接测试结果。代理修改展示受影响的连接；账号身份、代理连通性和具体操作权限分别显示。

验收标准：

- 能验证并保存正确的 AWS 账号身份；多个连接指向同一账号时不会重复建立资源归属。
- 两个账号并发请求时不串凭据、代理或缓存；配置错误和代理故障均不回退直连。
- STS 获取与刷新也遵循连接出口。停用和轮换后，新操作不会继续获得失效的凭据或客户端。
- 数据库、响应、审计和错误日志不存在明文 AWS 密钥或代理密码；秘密读取受权限控制。
- 测试账号的身份查询和配置的代理链路通过真实验证；验证成功只表示身份/链路有效，不等同于具备所有 AWS 操作权限。

完成后可以安全接入团队的 AWS 账号，尚不开放云端资源创建。

## M3 可靠任务与任务中心

主要属主：operations；任务处理器保持消息适配职责。

交付内容：

- plans、jobs、job_items、job_steps、job_attempts、job_events 和 outbox，保存输入快照、执行器版本、授权执行人及连接版本。
- 操作注册与 Validate、Plan、Execute、Reconcile 能力；先用可控模拟执行器验证完整路径。
- 事务内建任务及 outbox、发布器、Asynq 消费、步骤租约与执行代号、到期扫描和丢失消息补投。
- 有界重试、截止时间、取消未执行步骤、部分成功、needs_attention 和人工恢复入口。
- 任务列表、详情、逐目标结果、审计关联和 SSE 进度；断线后按事件序号补读，必要时回退轮询。
- 在后续写步骤重新检查授权、凭据状态和出口版本，记录每次尝试使用的实际配置。

必须覆盖的故障场景：

| 场景 | 期望结果 |
| --- | --- |
| 数据库提交后、消息入队前退出 | outbox 恢复投递 |
| 入队成功后、发布标记保存前退出 | 重复消息不重复推进已完成步骤 |
| AWS 接受请求后响应丢失 | 进入结果核对，不能直接再次创建 |
| Worker 租约过期或进程被终止 | 接管者先核对，过期执行者不能覆盖状态 |
| Redis 丢失待消费消息 | 根据数据库中未完成步骤补投 |
| 任务执行期间撤销授权或停用代理 | 停止新的写步骤，已有请求保留可核对记录 |
| 批次中部分目标失败 | 保留成功结果，仅处理失败目标 |

验收时必须在真实 PostgreSQL/Redis 上验证故障窗口。Asynq 重试和单次正常执行成功不能代替这些验收。

完成后才允许接入真实 AWS 写操作。

## M4 资源查询与同步

主要属主：inventory，以及按需求建立的 AWS 服务模块。

交付内容：

- 账号与区域选择、分页、过滤、资源概要和详情；首批读取范围与 M5 的业务闭环保持一致。
- 通过任务系统执行跨账号/区域刷新，记录同步范围、最后成功时间、错误和失效状态。
- 统一资源身份、权限过滤及缓存更新；AWS 返回状态与面板观测时间同时可见。

验收标准：

- 成员只能查看获授权账号的资源、同步任务及对应事件。
- 分页完整、局部失败可见；权限不足、区域不可用或网络错误不会被误判为资源已删除。
- 手动刷新和定时刷新不会并发破坏同一范围的快照。
- 在测试账号核对资源 ID、数量和状态，并验证代理故障时页面明确显示旧数据及刷新失败。

完成后可以作为团队的只读资源工作台使用。

## M5 首个业务闭环

建议第一条闭环为：选择 AWS 账号和区域，按需要启用区域，再批量创建 Lightsail，持续展示每个目标的结果。此处为优先级建议，进入阶段时再确定首批区域、套餐、镜像和网络配置范围。

按两个可独立验收的增量交付：

| 增量 | 交付内容 | 关键验收 |
| --- | --- | --- |
| M5a 区域操作 | 状态展示、批量启用、状态轮询和失败处理 | 已启用状态被正确识别；等待期间不占住长时间执行槽；重启后继续核对 |
| M5b Lightsail 创建 | 目标与参数预览、批量创建、资源引用与逐项结果 | 重复提交与超时不会盲目重复创建；名称冲突不冒认已有资源；失败目标可以单独处理 |

每次任务展示目标账号、区域、数量、关键参数及可能产生费用的资源。执行前检查可查询的权限、可用性和配额；检查不能替代 AWS 执行时的最终判定。

实例创建、云端可用、初始化脚本完成是不同的状态。接入脚本后要分别定义成功判据，不能用 API 请求成功代替初始化成功。

验收使用指定的测试账号和明确的测试资源范围，记录创建、查询、重试及清理结果。清理只针对本轮测试确认归属的资源，保留失败后的资源清单以便处理。

## M6 首个内部版本验收

交付内容：

- 实际构建并运行 Compose，验证空数据卷初始化、迁移身份和运行身份、启动顺序与健康检查。
- 完成从 M1 到 M5 的浏览器和真实 AWS 联调，覆盖至少两个连接及独立出口。
- 演练数据库与主密钥备份恢复、队列恢复、运行中任务重启、升级期间执行器版本兼容。
- 补齐部署、IAM 接入、代理诊断、审计查询和失败任务处理文档。
- 依据真实批量任务结果设置默认并发、超时、重试和保留期；按部署需要接入追踪导出器。

发布条件：常规检查、竞态检查、迁移/队列故障验证、容器实际运行和所选 AWS 闭环全部有结果记录。主密钥与数据库的恢复演练必须能还原可用连接；未通过的 AWS 能力在界面中保持未开放。

M6 完成后交付首个内部可用版本。功能数量以已验证的闭环为准。
